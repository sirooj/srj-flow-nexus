## 6. Concurrency, throttling, deduplication

**Multiple candidates may be alive concurrently.** The single-candidate model is removed by ruling: *"Multiple setups could be considered at a time but only one valid setup could be executed per session."* Exception explicitly blessed: a London setup still running plus a valid NY setup → both are taken, **even if they contradict**.

**Arrival order governs across time.** The first candidate to complete executes. A later higher-tier candidate does **not** displace it, and once a setup is executed the window is closed even to a higher tier. Operator: *"i will always execute the first one, the later higher POI does not get executed… if i have executed the first trade, i would not execute other trade even it's from higher hierarchy."*

This **overturns** v3's across-time tier-replacement reading of Step 8 / D-3 / G-2, which was an inference and not a ruling.

**Anchor tier governs a same-bar tie only.** Where two candidates complete on the same bar, the highest anchor tier wins. Below tier, tie-breaks are engineering determinism only, never strategy.

**One *valid* setup per pair per session.** *"i only take one setup per pair per session."* Maximum six trades a day across three pairs and two windows. One instance per symbol, so "per pair" is automatic; a cross-symbol throttle is not expressible in this architecture and must not be attempted.

**A rejected setup consumes nothing.** *"one valid setup, not invalid setup that got rejected."* The same POI may be re-approached in the same direction later in the same window after a rejection. Measured: **58% of candidates** (195 of 337) belong to a key with more than one attempt, so this is structural rather than exceptional.

**Deduplication is while-alive only.** A retest matching a live candidate's **(window, direction, anchor line)** key **updates** that candidate; it does not create a second one. Structural key — no bar count, no time window. Measured requirement: **145 of 446** suppressed retests share a live candidate's exact key, so without the merge a concurrent model inflates with logical duplicates.

**A candidate abandoned on the RR gate does not consume the window.** The operator anticipates exactly this: *"i would probably first, not execute the first trade cause there is a near (less than 1R TP)."*
